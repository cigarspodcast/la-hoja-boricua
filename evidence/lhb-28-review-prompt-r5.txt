DESIGN IN BRIEF.
Server: functions/api/mihoja.js and functions/_lib/mihoja.js on the existing table mihoja (migration 0002, no new migration). GET /api/mihoja returns { rev, schema, doc, updated_at } (no copy: rev 0, schema null, doc null). PUT { schema, doc } needs Content-Type JSON (415), If-Match with the rev the client saw (428 without or malformed), a valid body (400 bad-body, schema-unsupported when schema is not an integer 1; bad-doc; 413 too-big above 5000 entries per list or 900000 characters). If-Match 0 does INSERT ... ON CONFLICT(user_id) DO NOTHING; a positive rev does UPDATE ... SET rev = rev + 1 WHERE user_id = ?1 AND rev = ?5; zero changed rows returns 409 with the current copy. Both need requireProfile (401 no session, 403 no profile). D1 errors return 503, a row with unparseable JSON returns 500 corrupt.
Merge: site/sync.js window.LHB_MERGE.merge(base, local, remote, {prefer}). base is the copy both sides had at the last sync. Records with id (humidor, diario): one side only, kept unless the base had it unchanged (then it was deleted by the other side); both sides, equal then kept; only one side changed relative to base then that side wins; both changed then the newer actualizado/fecha wins, then prefer local when asked (import), then the greater stable JSON, so merge(b,l,r) and merge(b,r,l) agree. favs are sets with base-aware removal; pasaporte maps take the earliest date; ratings take the greater value; unknown top-level keys travel; draft, cambios, respaldo, recordarDespues, migrado and sync are local-only and never travel. Import of a respaldo file uses the same function with base null and prefer local.
Engine: window.LHB_SYNC(D) with every effect injected (storage, Clerk, fetch, timers, toast). once(): needs a signed-in account whose Clerk user matches the stored account; if the stored sync meta belongs to another account, the old local copy is parked under lhb_mihoja_v1_de_<sub> and Mi Hoja starts empty for the new account (nothing of the old account is uploaded); loop up to 4 times: GET, reject schema > 1, base = last synced copy unless the phone is empty while the base had data and nobody wrote since (then the emptiness is a loss, not a deletion, and the account copy is pulled), merge, PUT with If-Match unless the merged copy equals the remote, on 409 loop again with the new copy, then apply the result locally (3-way merge with anything written during the flight), write the sync meta { sub, rev, base, at, dirty }. run() is single-flight, up to 3 passes, retries with backoff 20 s, 40 s, 80 s, 160 s, 300 s; changed() (called by hoja.js write() after every save) debounces 2.5 s; start() listens for online and visible (30 s minimum age) and syncs 1.5 s after opening when an account is stored. hoja.js also calls SYNC.run when Mi Hoja opens (20 s minimum age) and shows a status line in the Respaldo panel; the backup banner text no longer says everything lives only on the phone.
