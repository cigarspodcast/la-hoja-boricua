## Findings (each rests on the measurement named; each becomes its own Backlog ticket)

1. HYPOTHESIS CONFIRMED: the map library loads on every first visit to /. vendor-leaflet.js (147552 bytes resource, 44519 transferred) and vendor-leaflet.css (3096 transferred) are requested at 228 to 233 ms, beside every app script, although the map only appears on #/lugares. Basis: the waterfall above, median-LCP run. All 10 scripts together: 160108 bytes transferred.
2. LCP 3249 ms median [3246 to 3255], "needs improvement" (good is under 2500 ms). The LCP element is the splash image div#campo > div#cz > div.lay > img.campo-bg. In the median run the image itself arrives fast (time to first byte 209 ms, load 87 ms), but its render is delayed 2363 ms. That points at the splash animation, not the network. Basis: lcp-breakdown-insight, run 3.
3. Images: Lighthouse estimates 253 KiB of image savings and 450 ms off LCP. Example: cigar thumbnails of 17 to 41 KB are drawn at about 159 by 81 px. 41 images, 419689 bytes transferred. Basis: image-delivery-insight and network-requests, run 3.
4. Speed Index 5371 ms median [2847 to 5396], "poor" (good is under 3400 ms). It moves with the splash: run 1 had Speed Index 2847 ms but CLS 0.145, from footer.seo-foot shifting; runs 2 and 3 had CLS 0. So the splash timing is bimodal across runs (1 of 3 different). Basis: the per-run figures (run 1: score 78, LCP 3255, TBT 373, CLS 0.145, SI 2847; run 2: 87, 3246, 151, 0, 5371; run 3: 87, 3249, 126, 0, 5396).
5. Render-blocking CSS: styles.css (15072 bytes transferred) blocks first paint for an estimated 150 ms of FCP. vendor-leaflet.css also blocks (estimate not given). Basis: render-blocking-insight, run 3.
Not ticketed (estimated savings too small to act on): cache headers 4 KiB, legacy JavaScript 10 KiB, unminified JavaScript 3 KiB, each with 0 ms LCP and FCP impact. Healthy: TTFB 110 ms median, FCP 999 ms, TBT 151 ms.
