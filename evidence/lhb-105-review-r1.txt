The fix (site/sync.js only):

If the mark cannot be written, isolate returns false and nothing else is touched. If iso1 throws, the key stays and lapses after SWITCH_TTL (30 s), which models a tab that closed mid-switch.
- switching() scans the keys with that prefix and is true while any well-formed mark is within SWITCH_TTL of now (either direction). A read that throws propagates, and once() turns it into fail 'storage', as the other storage reads there do.
- once0() checks switching() right after it reads ep0, and returns fail 'switching' (retried by run()'s backoff) while a mark is fresh.
- alive() is unchanged. Reasoning: the mark is written before the new epoch, and the pass checks the mark after it reads ep0. So a pass either read the new epoch (the mark was already there, so it does not start, unless the switch already ended, when the copy and owner are consistent) or read the old one (the new epoch kills it at its next alive()). A pass alive before the switch began is already stopped by the epoch, as on main.
- Contract impact: a new localStorage key family, lhb_mihoja_v1_cambio.<tab>, with a version field v:1. Nothing else reads keys under that prefix (hoja.js reads only lhb_mihoja_v1_de_*, the owner and the exit fence).
