+# La Hoja Boricua: guide for developers and AI coding assistants
+
+This file is the single source of instructions for anyone working on this repository, human or AI. Codex, Cursor, Aider, Gemini CLI, GitHub Copilot, Claude Code and similar tools read it (some through the short pointer files `CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md`). Paste it into any other chat-based assistant before asking it to change code.
+
+For the state of the project, the accounts it uses and the open work, read `docs/HANDOFF.md`.
+
+## What this is
+
+La Hoja Boricua (https://lahojaboricua.com) is an installable web app (PWA) about Puerto Rican handmade cigars: makers, cigars, lounges and shops, events, guides, and a personal section, "Mi Hoja" (humidor, tasting diary, passport, favourites), that syncs to a user account. Spanish is the primary language; every screen also has English. It works offline once loaded.
+
+## Stack, in one paragraph
+
+Plain HTML, CSS and JavaScript in `site/`, with no framework, no npm dependencies and no build step for the app itself. Python scripts in `tools/` generate the static pages and the data bundle from JSON in `data/`. Hosting is Cloudflare Pages (project `la-hoja-boricua`), which publishes `site/` from `main`. A small API runs as Cloudflare Pages Functions in `functions/` on a Cloudflare D1 (SQLite) database. Sign-in is Clerk. Tests use Node's built-in test runner.
+

+## Commands
+
+Run from the repository root.
+
+```bash
+# tests (needs Node 22.5 or newer for node:sqlite; CI uses Node 24; Python 3 must be on PATH as "python")
+node --test test/site.test.js
+
+# after editing anything in data/: regenerate pages, sitemap, robots and the bundle
+python3 tools/build_lugares.py
+python3 tools/build_artesanos.py      # also runs build_cigarros.py
+python3 tools/build_guias.py
+python3 tools/rebuild_bundle.py
+
+# look at the static site locally (the API does not run this way)
+cd site && python3 -m http.server 8080
+```
+
+Other tools: `tools/build_icons.py` renders the PNG icons and `og.jpg` from the SVG masters in `site/icons/`; `tools/build_thumbs.py` makes photo thumbnails; `tools/build_llms.py` writes `site/llms.txt`; `tools/build_data.py` creates the JSON in `data/` from a new research file.
+
+CI (`.github/workflows/test.yml`) runs the tests and the generators on every push and pull request, and fails if the generated files committed in git differ from what the generators produce. So always commit generator output together with the data change.

+## Deploying
+
+- Push a branch: Cloudflare Pages builds a preview at `https://<branch>.la-hoja-boricua.pages.dev`. Previews use the preview database and Clerk's development instance.
+- Merge to `main`: Cloudflare Pages deploys production at https://lahojaboricua.com within a couple of minutes. Cloudflare runs the generators on every deploy.
+- Rollback: in the Cloudflare dashboard, Workers & Pages, la-hoja-boricua, Deployments, choose the previous production deployment and "Rollback to this deployment". Or revert the merge commit on `main`.
+
+## Rules that keep the site working
+
+1. **Bump the service worker version on every release.** In `site/sw.js`, change `const VERSION='lhb-vNNN'` to the next number. The tests pin the version in many places, so update every pin as well: search `test/site.test.js` for the old `lhb-vNNN` and replace them all. Without the bump, returning visitors keep the old files.
+2. **Add every new file the app needs offline to `SHELL` in `site/sw.js`.**
+3. **Every visible string goes through the translation tables.** Add the key to both the `es` and the `en` table in `site/i18n.js` and use `tt('key')` (or `I.t`). The tests scan for untranslated text.
+4. **Never edit generated pages.** Change `data/` or the generator in `tools/`, then rerun the generators.
+5. **Database changes are additive and tolerant.** Add a new numbered file in `migrations/`. Code must keep working before the migration is applied (see `functions/api/me.js`, which falls back when the `lang` column is missing). Apply it to the preview database first, then production.
+6. **Secrets never go in the repository.** The repository is public. Server secrets live only in the Cloudflare Pages project settings. Clerk's publishable keys in `site/hoja.js` are public by design; the secret key is not.
+7. **Mi Hoja is local first.** It is saved on the phone (localStorage) and synced to the account by `site/sync.js`. Changes there must survive offline use, two open tabs, and a sign-out while a sync is in flight. The existing tests cover many of these cases; run the whole suite.
+8. **Keep it dependency free.** No frameworks, bundlers or npm packages in `site/`. Leaflet is vendored as `site/vendor-leaflet.*`.
+9. **Accessibility and contrast are tested.** Some CSS changes need the pinned contrast or paint tables in the tests updated on purpose. Check that the new colours really pass, instead of just changing the numbers.
+10. **Comments in the code are in Spanish.** Match the surrounding style when adding code.
+
+## How to make a change safely (any assistant)
+
+1. Read the relevant file and its tests before editing (search `test/site.test.js` for the function or file name).
+2. Write or adjust a test that fails before the change, then make it pass.
+3. Run the full suite: `node --test test/site.test.js`. Expect 0 failures (one test is skipped on purpose).
+4. If you touched `data/` or a generator, run the generators and commit their output.
+5. If the release changes anything the app caches, bump `VERSION` in `site/sw.js` and its test pins.
+6. Push a branch, check the preview in a phone-sized browser window in both Spanish and English, and in light and dark themes, then merge.

+## Database
+
+D1 databases: `lhb-prod` (production) and `lhb-preview` (previews), in the same Cloudflare account as the Pages project. The schema is the migrations in order, `0001` to `0009` at the time of writing. To apply a new one, either:
+
+- Cloudflare dashboard, Storage & databases, D1, choose the database, Console, paste the file's SQL and run it (preview first, then production); or
+- `npx wrangler d1 execute lhb-preview --remote --file migrations/00NN_name.sql` (then `lhb-prod`), with a Cloudflare API token that has D1 edit rights on that account.
+
+Read-only checks can use the same console with `SELECT`.

+## Known behaviour worth knowing
+
+- The live JavaScript files are served with `Cache-Control: max-age=14400`. A browser that has no service worker yet can keep last release's files for up to four hours. Visitors with the service worker get new files when the new `VERSION` installs.
+- On a first visit the app asks for the language before anything else; the choice is kept in the `lhb_lang` cookie and, when signed in, on the account. The device's choice wins over the account's.
+- Branch previews are not indexed (`site/_headers`).
+- Installing the app (LHB-121): an inline script in the head of `site/index.html` keeps the browser's `beforeinstallprompt` event in `window.__lhbBIP`, before any deferred script runs. In `site/app.js`, `installHow()` decides how this browser installs, and every Install button (top bar, home page, menu, reminder bar) goes through `doInstall()`; the guides it opens are the `instalar` sheet in `site/hoja.js`. Change that logic there, not in a second handler. A real install can only be tested on a phone or a desktop Chrome/Edge: the test suite checks the decisions, not the browser's own prompt.

+# La Hoja Boricua: AI routes of the previous team (LHB-79)
+
+These are the rules for `tools/ai_routes.py`, the previous team's client for three paid AI services, with keys kept in their own Windows user environment. Nothing in the site or its tests needs these services, and a new team does not need these keys. The rules are kept here for anyone who chooses to use that client. Guidance for working on the site is in `AGENTS.md`.
+
+## AI routes
+
+LHB calls three AI services directly, through its own client `tools/ai_routes.py`, with keys held in the Windows user environment. It never uses the estate gateway or the C10 routing pack.
+
+| Route | Variable | Call |
+|---|---|---|
+| TypeSafe Jev | `TYPESAFE_API_KEY` | `jev_choice(...)`: POST `https://api.typesafe.ai/v1/systemone`, model `jev-latest` |
+| OpenCode Go | `OPENCODE_GO_API_KEY` | `opencode_chat(...)`: POST `https://opencode.ai/zen/go/v1/chat/completions`, Go-plan models only |
+| Together (fallback) | `TOGETHER_API_KEY` | `together_chat(..., case=...)`: POST `https://api.together.ai/v1/chat/completions` |
+
+Rules that travel with the access:
+
+- **Keys.** A key is read from the environment at the moment of the call. It is never printed, logged, written to a file, committed, quoted in a comment, or stored in any tool's credential store, opencode's own login included. Verify a key by presence and by use only.
+- **Jev data class.** Jev takes data class none only: synthetic text or public site content. Ticket text, code, review notes, database contents, Clerk data and anyone's personal data never go to Jev.
+- **OpenCode Go endpoint.** OpenCode Go is called under `https://opencode.ai/zen/go/v1` only, never anything under `https://opencode.ai/inference`, which is metered.
+- **OpenCode Go session header.** Every Go call carries `x-opencode-session` (the client sends one id per process, or the caller's `session=`); without it Go answers 400 MissingSessionID. Go is meant for coding-agent traffic and is monitored for abuse, so keep calls few and purposeful.
+- **Together serverless models only.** Together answers 400 for a model that needs a dedicated endpoint (for example `meta-llama/Llama-3.3-70B-Instruct-Turbo`); pick from its serverless list.
+- **Together is a fallback only.** Call it when the model is not on the Go plan (`case='not-on-go'`) or when an OpenCode call is refused because the subscription is used up (`case='go-exhausted'`). The client refuses any other case.
+- **Spend.** Jev and Together are paid. Before the first Jev call on a ticket, post a reason comment on that ticket. At most 10 Jev calls per ticket go without the owner's yes.
+- **Call log.** Every call appends one line to `evidence/ai-calls.log`, tab-separated: UTC time with Z, route, model, ticket, reason, HTTP status. It holds no key and no request or response text.
+- **A refusal is a result.** A refused call (401, 403, 429) is recorded, never retried in a loop.
+
+Tests: `python -m unittest tools/test_ai_routes.py` (no network). Proof: `python tools/ai_proof.py <base commit>` (one paid call per route, then the leak check). Leak check alone, no call: `python tools/ai_leakcheck.py <base commit>`.

+# La Hoja Boricua: independent brand and architecture assessment
+
+Alfredo Medina. October 29, 2026 (UTC-4). Read against production (lahojaboricua.com, main b8b2b89) at phone width (390 by 844) and desktop width (1366 by 860), and against the code on main. Earlier proposals (the facelift package) were not used as a reference.
+
+## Verdict
+
+The foundations are right: a crawlable site of real pages with an installable app on top, a local-first Mi Hoja that syncs to the account, a palette rooted in the place, and a sound body typeface. What is wrong is coherence. The app speaks with three display voices, three wordmarks, five illustration styles and three navigation systems, and on a computer it is a phone column with a phone tab bar stretched across the screen. Fix coherence first; most of it is subtraction.
+
+## Bless (keep, and build on)
+
+- **Architecture: static pages plus app.** Every cigar, maker, lounge and guide has its own crawlable page (49 cigar, 33 maker, 43 place, 22 guide pages, plus 124 English pages), with sitemap, canonical links, structured data and llms.txt. That is the right answer to a hash-routed app (#/catalogo), and it is how the site gets found.
+- **Local-first Mi Hoja with account sync.** A lounge has poor signal. Saving on the phone first and settling with the account later is the correct model, and the recent sync work makes it safe across tabs.
+- **The palette.** Paper #F4F1EA, tobacco green #344C31, and the flag's celeste and red as accents. It belongs to Puerto Rico and to tobacco, and it is already built as role tokens with a contrast test. Keep it.
+- **Figtree for the interface and body text.** Clear at small sizes, warm, self-hosted, preloaded, font-display swap.
+- **Fraunces for content headings.** A soft, literate serif that suits names of cigars, makers and places.
+- **The mark.** A tobacco leaf whose rib is a road. It is specific to this product and reads at icon size.
+- **Five tabs on the phone, Spanish and English, the intro video** (owner ruling: the intro stays).
+
+## Challenge (change)
+
+### 1. One display typeface: retire Shrikhand
+Shrikhand is a 1970s fat italic. It reads as diner signage or surf merchandise, not as the craft and heritage of a tobacco farm, and it competes with Fraunces: the home page shows a Shrikhand hero, a Fraunces section title and Figtree labels in one screen. Fraunces already carries character. **Do:** use Fraunces as the only display face, in its variable form (weight and optical size axes, Latin subset, self-hosted), heavier and at a large optical size for page titles. Body and controls stay Figtree.
+
+### 2. One lockup, everywhere
+Today there are three wordmarks: the app header (Shrikhand, stacked, with MADE IN BORINQUEN), the static pages (plain Fraunces, no mark) and the intro (Shrikhand, one line). **Do:** one lockup, the leaf mark plus a Fraunces wordmark, in a horizontal and a stacked form, used in the app, every static page, the 404 and privacy pages and the share image. The tagline is **Hecho en Borinquen** in both languages: a tagline is part of the brand, not text to translate.
+
+### 3. One navigation system and one vocabulary
+Six destinations are reached through the tab bar, three shortcut chips on the home page, a menu sheet that lists them again, and four round header buttons (language, search, menu, account). The names drift: Catalog and Cigars, Artisans and Makers. **Do:** the tabs are the navigation (Cigarros, Artesanos, Lugares, Eventos, Mi Hoja and their English pairs, used identically in tabs, titles and links). The header keeps search, menu and account. The language switch moves into the menu. The menu holds only what the tabs do not: guides, the Tobacco Route, about, credits, privacy. The home shortcut chips go. The decorative hero card on the catalog (The Tobacco Route in Puerto Rico) becomes a real entry to the Route.
+
+### 4. Colour has meaning
+On an event card three buttons use three colours (celeste, outlined, red). Red is also the add button, sign-in, map clusters and the Full strength tag. **Do:** one primary action per view, filled tobacco green; secondary actions outlined; red is the brand accent for the single most important action (the add button) and for the flag stripe, never decoration; celeste is for links and the flag only. Strength tags use a neutral ramp, not alarm red.
+
+### 5. One illustration language
+Five styles coexist: the rendered 3D intro, a flat botanical flower on Places, a cartoon frog on Events, patterned placeholder cards for cigars without a photo, and real product photos on white. **Do:** the subject's own vernacular, the cigar band and the cigar-box lithograph: single-colour line art in tobacco ink with one accent. The frog and the flower are replaced by line-art headers in that style; cigars without a photo get a neutral line silhouette in the same frame as the photos, so the grid reads as one catalogue. The intro video stays (owner ruling) as the one cinematic moment.
+
+### 6. A real system: type scale, radii, spacing
+styles.css uses 23 distinct font sizes (9 to 30 px, including half pixels) and 16 border-radius values. **Do:** a six-step type scale and three radii as tokens, and rules read only tokens.
+
+### 7. A computer layout
+At 1366 px the app is a phone column and its tab bar spans the full width, Catalog at the far left and Mi Hoja at the far right. **Do:** from 900 px the navigation moves to the top bar, the catalogue grid widens to three or four columns, and the tab bar is hidden.
+
+### 8. A dark lounge theme
+Lounges are dim and the app is used at night. **Do:** a dark theme from the same role tokens, following the phone's setting, with a manual choice in the menu. The token work already done makes this cheap.
+
+### 9. Static pages share the app's chrome
+The static pages are functional but look like a different product. **Do:** the generators emit the same lockup, header, tokens and type as the app, so a visitor from search lands on the brand, not on a bare list.
+
+### 10. Avatar placeholder
+A star in a circle does not say account. **Do:** a person glyph when signed out, the picture or initials when signed in.
+
+## Architecture: measure before changing
+
+About 400 KB of unminified JavaScript loads on every first visit (hoja.js 165 KB, data bundle 97 KB, app.js 67 KB, sync.js 33 KB), with no build step; the service worker caches it after that. Mi Hoja and sync (about 200 KB) only matter to people who sign in. **Do:** measure first-visit cost with Lighthouse on a claimed host; if it matters, add a minimal build (minify, and load Mi Hoja and sync on demand). This waits until the sync work (LHB-104) merges, because it touches the same files. Not verified here: the actual first-visit timings.

+# La Hoja Boricua: facelift review and staged integration plan
+
+Alfredo Medina. Reviewed October 27, 2026 (UTC-4). Source: the Codex handoff package and the 3D source package, read against the current main branch of the app.
+
+## Verdict
+
+Adopt the palette, the video, the menu grouping, the accessibility fixes and the voice. Rebuild the logo. Do not adopt the points system as proposed. Do not copy the package's web folder or apply its patch as it stands: it was cut against an older production snapshot, and it gets its light theme by redefining the old dark-theme color names. Stage the whole facelift on a preview address for Sergio. Nothing goes to production until Sergio and the owner sign off.
+
+## What I checked myself
+
+- **The package is older than main.** Its account file is 7.9 KB and main's is 17.6 KB. Its index, app and profile files also differ from main. It has none of the static search pages (43 lounge pages plus the maker and cigar pages), the privacy page, the share image or the generators in tools. Port the changes as a diff on current main.
+- **The patch itself is small.** Ten files. About 100 changed lines across index.html, app.js and hoja.js, plus 191 lines of new CSS, a 26-line icon and menu file, and a 27-line intro player. The facelift is smaller than it sounds.
+- **The light theme is a hack.** Main is a dark app (cream text on dark green). The package flips it to light by redefining --cream as dark ink and --gold as tobacco green. Main uses var(--cream) on 34 lines and var(--gold) on 40, and has about 140 hex and 60 rgba literals in styles.css, 62 hex in app.js and 64 in hoja.js. The package's own reviewer found four contrast failures that come from this (an event date at 1.29 to 1 is the worst). Every screen I built for the profile work (avatar header, profile editor, People search, follow buttons) was drawn for the dark theme and needs the same audit.
+- **The palette has limits as text colors.** I computed contrast. On paper #F4F1EA: tobacco 8.37, red 4.59, amber 2.98, celeste 2.44, sun 1.63. Dark ink on celeste is 4.62 (fine), dark ink on sun 6.93 (fine), dark ink on amber 3.78 (large bold text only), white on celeste 2.75 (fails). So celeste, amber and sun are fills, never text on paper, and amber needs a darker companion for small text.
+- **The 3D source zip is intact.** 108 files, no bad entries, SHA-256 cad5ceda348ac1a7df514300060ab78c11e530db3cd17e1acb54e4d22fb802cd. The scene file alone is 339 MB, so it stays out of the repository (see the plan).
+
+## Adversarial review
+
+### Logo: needs improvement
+- The mark reads as a stick laid across a leaf, or a quill. The idea (the vein is also a path, two gaps are discoveries) does not read, and the knots on the stem make it look like a twig.
+- It is a generic ovate leaf. Any wellness or organic brand could use it. Tobacco has a clear signature: a broad leaf with a pointed tip, a strong central rib and curved side veins. The package's own video poster already shows that leaf in the roadside plants.
+- At 32 px it reads as "a leaf". At 16 px the knots and the short side branches will merge.
+- Keep the wordmark: Fraunces for La Hoja and widely spaced Figtree for BORICUA works and matches the type system.
+- Direction: a tobacco-leaf silhouette whose rib curves like a road and ends in a small round dot (a stop on the route). Make three variants, test each at 16, 32 and 180 px, in one color, and inside the maskable safe zone. Trademark clearance is not done and is not the app's job to claim.
+
+### Palette: adopt, but build it properly
+- Real semantic tokens (surface, on-surface, accent, accent-ink) instead of inverted aliases. No token whose name says the opposite of its value.
+- A contrast test in the suite that computes each text and background pair we use and fails below 4.5 (3 for large text).
+- Audit every color literal in styles.css, app.js, hoja.js, the static pages and their stylesheet l.css, and the privacy and 404 pages. Otherwise the site ends up as two brands.
+- Update manifest theme_color and background_color (both are still the dark green) and the share image.
+
+### Navigation and home: adopt the structure, fix three things
+- The grouping (Descubre, Tu experiencia, En comunidad, La app), the destination-specific icons and the current-page marker are better than what we have.
+- The menu in the package is a second hard-coded list. Generate it from the route table so a new destination cannot be left out. It must include what we built after the snapshot: Personas search, profile editing.
+- The Cigarros card steals focus into the search box and raises the keyboard. Scroll to a heading instead.
+- The home page puts an introduction and three cards above the first result. Compact them for returning visitors and verify that results are reachable at 320 by 568.
+- Keep the five tabs and the plus button.
+
+### Intro video: adopt the clip, change the policy
+- It plays once per session. On an installed app every cold launch is a new session, so people would see it every time. Play it on first run and then at most once every 14 days, with Ver intro in About.
+- The video element has no poster, so there is a blank paper flash until it plays. Add a small webp poster (the package posters are 540 to 600 KB, too heavy).
+- Good as built: muted start with a sound button, skip, Escape, reduced motion, data saver, deep links, hard time limits, no loop.
+- Credit wording must be written as what is true. The package's own reviewer found the credit claiming the plate is retained before the frame was inspected. Inspect a full-size frame, then say it.
+- Owner gates: the bus is another artist's illustration (Calle Pomarrosas). The package says not to imply endorsement but nothing in it shows permission. Written permission should be on file before this is public. Also confirm the 3D generator's terms allow commercial use, and ship an in-app audio credits page (CC BY 4.0 requires it).
+
+### Accessibility fixes in the patch: adopt now, separately
+Modal focus containment, the persistent results status region, catalog filter focus, and the camera and gallery focus ring are real defects on main today, not branding. One finding is still open: the backup import label has tabindex 0 and a hidden file input. Also remove the portrait-only orientation lock in the manifest. These can land before the visual work.
+
+### Language
+All new copy in the package is Spanish text inside scripts. Main has the i18n system with a scan test, and Sergio is reviewing the English draft. Every new string must be a key with Spanish and English values or the scan test fails.
+
+### Points and levels: do not adopt as designed
+- The design is careful (no purchases, no streaks, no rankings, the top level reachable without travel or smoking). Keep those rules.
+- The machinery is the problem. Event ids, daily caps, idempotent awards and undo are built for rewards that have outside value. These points have none and stay private. Points that are a pure function of the saved passport and diary data cannot be double-counted and undo by themselves.
+- Several rules depend on things that do not exist: six learning modules and a "what I learned" prompt on five maker stories. Without that content, the top level cannot be reached at all.
+- Some rules depend on history ("first refinement of an entry"). State-based versions are needed (for example, an entry that has observations in two or more groups).
+- 165 points in total, with level 5 at 110, is a very short game. Calibrate it with real use before showing numbers.
+- Our passport already syncs between phones. Any new learning record belongs inside that same document (the sync branch already carries unknown fields through its merge), not in a second store.
