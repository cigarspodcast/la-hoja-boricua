What was built:
- Server:
  - functions/_lib/feed.js feedOf(db, me, cursor) runs one SQL query: follows (follower = me), joined to profiles (hidden = 0), joined to mihoja, then json_each over '$.diario'.
    - An invalid document, or one whose diario is not an array, contributes nothing.
    - It keeps object entries with json_type(publica) = 'true', the same rule as passport.js publicDoc (publica === true).
  - Sort key:
    - the day, consumido when it has the YYYY-MM-DD form, else '' (last, like publicEntry);
    - then the handle;
    - then pos, the entry's ROW_NUMBER among that person's public entries counted from the oldest. A new entry, unshifted to the front of the diario, moves nobody.
    - Order: day DESC, handle DESC, pos DESC. That is the profile order: newest day first, and on the same day the diario order.
  - The cursor is "day~handle~pos" ("-" for no day). It has no entry id and no saved date, and pos counts only public entries.
  - parseFeedCursor rejects anything else (400 bad-cursor).
  - PAGE + 1 rows are read to know if there is a next page.
  - Each entry goes out through passport.js publicEntry (the closed list), with the author's handle, display_name and checkAvatar'd avatar_key. user_id never goes out.
  - isBlocked is called per author, and a blocked author is skipped. The cursor stays the last row read.
- functions/api/feed.js: GET with requireProfile (401 no-session, 403 no-profile).
- Client, site/hoja.js:
  - a Siguiendo entry in the Mi Hoja subnav (#/mihoja/siguiendo), and vSiguiendo;
  - each card is the Personas personRow for the author (link to #/u/<handle>) plus a button with the entry, closed by pfEntry and escaped;
  - tapping the button opens pfResSheet, the profile's review sheet;
  - "Ver más" sends the cursor; an empty feed links to #/mihoja/personas; an error shows "Intentar otra vez" for the same page;
  - a stale answer (seq) or a page that is gone paints nothing, and api()'s go check (LHB-60) keeps a request from going out once its page is gone or a newer one started;
  - tagChips gained an inline flag, so the chips are a span inside the button (a div cannot be).
- Styles: .feed, .feed-c, .feed-b and .feed-n. Cache: lhb-v89 (LHB-34, still in review, holds v88).
